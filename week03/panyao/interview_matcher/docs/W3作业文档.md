# W3 作业：Agent 反思设计模式 + 工具调用

## 1. 本周目标

在 W1 工具调用闭环、W2 简历标签抽取的基础上，本周实现：

- **反思设计模式**：每次工具返回后先做可信度 / 合规反思，把问题回灌给模型修正，而不是拿到结果直接作答；
- **真实工具接入**：四个本地可运行的内部工具（只读拉简历、查时段、读 HR 覆盖、生成推荐卡片草稿），工具函数真实执行本地逻辑，不返回写死的 mock 数据；
- **守住业务红线**：只读不回写、推荐不派单、时段不锁定、人工指定优先级最高。

代码位置：`src/interview_matcher/week3/`（`tools.py` 工具 schema 与实现、`reflection_agent.py` 反思循环、`hr_data.json` 本地样本），入口 `uv run w3-agent [问题]`。

## 2. 总体反思循环流程

```
用户问题
  │
  ▼
messages = [system 边界提示, user 问题]
  │
  ▼
LLMClient.chat(messages, tools=TOOLS)
  │
  ├─ 模型返回 tool_calls ──────────────┐
  │                                    ▼
  │                          逐条解析工具参数
  │                                    │
  │                                    ▼
  │                          TOOL_IMPL 本地执行工具
  │                                    │
  │                                    ▼
  │                          工具结果回灌 role=tool
  │                                    │
  │                                    ▼
  │                          reflect() 反思结果
  │                          （空结果 / 未连适配器 / 无时段 / 有无人工指定）
  │                                    │
  │                                    ▼
  │                          反思意见回灌 role=system
  │                                    │
  └────────────────────────────────────┘ 回到下一轮 LLM 调用

  模型不再返回 tool_calls
  │
  ▼
输出最终回答，循环结束；超过 5 轮强制终止，避免无限调用。
```

反思节点只做校验和提示，不替代工具执行；反思意见包括：简历是否为空、适配器是否连通、时段是否可读、HR 覆盖是否存在、卡片是否仍待人工确认。

## 3. 工具一：fetch_resume_from_hr_system（只读拉简历）

**职责**：从招聘系统 / 飞书文档 / 本地文件只读获取简历附件文本；不回写招聘系统、不下载到长期存储。

```
模型工具调用
  │ 参数：resume_ref（路径 / 单据号 / 文档标识）, source（local_file | hr_system | feishu_doc）
  ▼
按 source 分支
  │
  ├─ local_file ─────────────────────┐
  │                                   ▼
  │                     resume_loader.load_pdf_text() 抽 PDF 文本
  │                                   │
  │                                   ▼
  │                     resume_loader.strip_pii() 行级脱敏
  │                     （电话 / 邮箱 / 链接 / 日期 / 院校 / 姓名 / 水印）
  │                                   │
  │                                   ▼
  │                     返回 { read_only: true, persisted: false,
  │                             text, text_length, pii_redacted: true }
  │
  └─ hr_system / feishu_doc ─────────┐
                                      ▼
                        适配器占位：返回 status=adapter_not_connected
                        （当前不发外部请求，不回写、不落盘）
  ▼
reflect() 反思
  ├─ 适配器未连：只能用本地可读文件，禁止编造外部简历内容
  └─ 文本为空：需让 HR 补附件或换来源，不硬抽标签
```

**返回要点**：`read_only=true`、`persisted=false`；外部系统接口留 TODO，后续在适配器内补只读 HTTP 调用。

## 4. 工具二：query_interviewer_calendar（只读查时段）

**职责**：只读查询面试官可面试时段，给出排期建议；不锁定、不预订会议。

```
模型工具调用
  │ 参数：interviewer_id, date_from（可选）, date_to（可选）
  ▼
读取 hr_data.json → calendar[interviewer_id]
  │
  ▼
按 date_from / date_to 过滤时段（字符串日期区间）
  │
  ▼
返回 { interviewer_id, read_only: true, locked: false,
        available_slots: [...], message: 仅建议不锁会 }
  ▼
reflect() 反思
  └─ 无可用时段：结果中标注不可约，禁止编造时间
```

**返回要点**：`locked=false`；最终排期仍由 HR 确认。

## 5. 工具三：notify_hr_override（读取 HR 手动覆盖）

**职责**：读取 HR 手动指定的优先面试官；人工结论覆盖规则排序，优先级最高。

```
模型工具调用
  │ 参数：candidate_ref, preferred_interviewer_ids（可选）, source（可选）
  ▼
入参优先判断
  │
  ├─ 传入 preferred_interviewer_ids ──► 直接使用该次人工结论
  │
  └─ 未传入 ────────────────────────► 读 hr_data.json →
                                      hr_override[candidate_ref]
  ▼
返回 { override_applied, preferred_interviewer_ids,
        priority: "manual_highest", rule_sort_locked: false, note }
  ▼
reflect() 反思
  ├─ 有人工指定：这些面试官必须排在规则结果之前
  └─ 无人工结论：按规则排序推荐，不冒充 HR 指定
```

**返回要点**：`priority=manual_highest`；工具只读取结论并置顶，不自动改派面试官。

## 6. 工具四：push_recommendation_card（生成推荐卡片草稿）

**职责**：把面试官推荐清单整理成待 HR 确认的卡片草稿；不自动派单、不通知面试官、不创建会议。

```
模型组装推荐列表
  │ 参数：candidate_ref, recommend[{interviewer_id, name, match_reason}],
  │       channel（group | private）, target（可选）, note（可选）
  ▼
逐条渲染卡片行
  │ 序号 + 工号 + 姓名 + 匹配理由
  ▼
返回 { card: { title, candidate_ref, channel, target, lines, note },
       pushed: false, auto_dispatch: false,
       requires_human_confirm: true }
  ▼
reflect() 反思
  └─ 卡片只是待确认草稿：不自动派单、不创建会议，必须提示由 HR 确认
```

**返回要点**：`pushed=false`、`auto_dispatch=false`、`requires_human_confirm=true`；真实飞书推送后续接适配器，当前只生成草稿。

## 7. 工具参数与返回对照

| 工具 | 关键入参 | 关键返回 | 边界 |
|---|---|---|---|
| `fetch_resume_from_hr_system` | `resume_ref`、`source` | 脱敏文本、`read_only`、`persisted` | 不回写、不长期存储；外部源适配器未连 |
| `query_interviewer_calendar` | `interviewer_id`、`date_from`、`date_to` | `available_slots`、`locked` | 只读建议，不锁会 |
| `notify_hr_override` | `candidate_ref`、`preferred_interviewer_ids`、`source` | `preferred_interviewer_ids`、`priority` | 人工置顶，不改派 |
| `push_recommendation_card` | `candidate_ref`、`recommend`、`channel`、`target`、`note` | 卡片草稿、`pushed`、`auto_dispatch` | 待 HR 确认，不派单 |

## 8. 合规边界（写进系统提示与工具返回）

- 候选人简历只临时读取、脱敏后使用，不入库、用完即删；
- 不评价候选人优劣、不打分淘汰；
- 推荐清单不自动派单，不直接通知面试官，不创建会议；
- 日历只返回建议时段，不锁定；
- HR 手动指定优先于规则排序；
- 工具未返回的面试官、时段、简历内容，模型不得编造。

## 9. 本地样本与待接适配器

`hr_data.json` 当前维护两份本地样本：

- `calendar`：面试官工号 → 可面试时段列表；
- `hr_override`：候选人标识 → HR 手动指定工号与备注。

后续接真实系统时只换数据源 / 适配器，不改工具接口：

| 待接能力 | 当前状态 | 后续接入点 |
|---|---|---|
| 招聘系统 / 飞书文档只读拉简历 | 适配器占位 | `fetch_resume_from_hr_system` 外部源分支 |
| 飞书群 / 私聊推送推荐卡片 | 草稿生成 | `push_recommendation_card` 增加真实发送适配器 |
| 面试官日历只读查询 | 本地 JSON 样本 | `query_interviewer_calendar` 接日历只读接口 |
| HR 手动结论回写读取 | 本地 JSON 样本 | `notify_hr_override` 接飞书消息 / 招聘系统 |

## 10. 运行与验证

```powershell
# 默认 demo：读 HR 覆盖 → 查时段 → 生成待确认卡片草稿
uv run w3-agent

# 自定义问题
uv run w3-agent "为 APP-123 准备面试官推荐清单"
```

已验证：

- 工程编译通过；四个工具可直接调用，返回字段与边界符合预期；
- `w3-agent` 控制台脚本已生成；真实网关（`DRY_RUN=0`，model `glm-5.3`）跑通默认 demo，工具顺序为 `notify_hr_override → query_interviewer_calendar → push_recommendation_card → 收敛`；
- 真实输出存档见 `docs/运行结果-W3.txt`：HR 置顶、只读时段、待确认卡片草稿三条边界均生效；
- 离线 `DRY_RUN=1` 仅用于无网关时跑通链路，不作为作业真实调用记录。
